# V8

The ledger for the next rebuild: what running v7 teaches about the design, one line each, newest first. Incidents and
their fixes live in docs/ISSUES.md; this file holds only what a fix inside v7 does not settle. The v8 iteration reads
this with docs/PROBLEM.md, docs/PRD.md and docs/ARCHITECTURE.md, and questions all four.

## Observed in v7 (from 2026-10-25)
- A run's lifecycle cannot be read from hook events: the start event races the agent's transcript, and a stop is a
  pause as often as an end. v7 now binds at the first command and ends on the hand-back call. v8: derive the run from
  the agent's transcript alone (first line = the brief, hand-back = the end); drop the start and stop events.
- A gate bound to `base` voids on every upstream merge, so every open change re-gates each time upstream merges
  (several times a day): one fork CI run per change per merge, minutes of pass time. v8: gate the merge GitHub already
  computes for the PR (mergeable state and upstream CI on the PR head) and keep the scratch merge only for changes
  without a PR.
- The train stops at the first unrecorded conflict and the integrator resolves one at a time; a rebuild with several
  stale branches takes one integrator run per conflict. v8: the rebuild reports every conflict in one run, or stale
  pinned branches are dropped from integration by a fact (their change is gone) rather than resolved.
- Findings are anchored on the approval record's timestamp, which the migration got wrong once and which has nothing to
  do with the maintainer. v8: anchor on our own last comment or push on the PR.
- The console spawns agents by hand with the Agent tool, so throughput is bounded by the user's presence and the agent
  count; a paused agent holds a slot. v8: measure how long listed spawns wait and decide whether the pass may spawn.
- The guard judges by command text, so a local `git remote set-url` naming upstream was denied while the pass's own
  `gh pr ready` runs outside the guard. v8: judge by effect (the remote resolved at push time, the repo named to gh)
  and nothing else.
- `events.jsonl` grows without bound and nothing reads it but people. v8: either drop it or make `hd` read it.
- The brief's first line is a protocol between three programs (steps, hook, the Agent tool prompt). v8: the run record
  should be written by the spawner, not parsed back out of a prompt.
- Repairs find orphans by the v7 run name; artefacts of earlier versions (v6 clones, state) are invisible to them.
  v8: name every artefact after the change, not the run, and remove it when the change is done.
